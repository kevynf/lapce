# Internationalization

Lapce's UI translations use flat TOML locale tables in
`lapce-app/assets/locales`. Locale files are embedded into the binary at
compile time, and English is the fallback locale.

## Runtime model

The supported UI language values are:

- `auto`: inspect the process locale environment and fall back to English;
- `en`: English;
- `zh-CN`: Simplified Chinese.

Use the shared `I18n` instance from `CommonData` in views. Ordinary UI text
uses `i18n.text(...)` or `i18n.text_signal(...)`; commands use
`command_text(...)`; settings use `setting_text(...)` and
`setting_value_text(...)`.

For Floem views, prefer a reactive producer such as
`label(i18n.text_signal("some.key"))` so a language change updates the view.
Calling `i18n.text(...)` while constructing a view snapshots the current
translation and is intended only for non-reactive values such as native dialog
titles or command metadata.

`I18n` is kept in `CommonData` rather than Floem's context because the pinned
Floem context store is runtime-global, while Lapce allows window tabs to have
independent workspace settings.

When a key is absent from the selected locale, lookup falls back to English and
then to the key itself. New keys must be added to every locale file; the
`locale_files_have_matching_keys` test checks this requirement.

## Key structure

Use responsibility-based prefixes for ordinary UI text:

```text
common.<action>
menu.<item>
panel.<panel>
file-tree.<item>
terminal.<item>
git.<item>
command.<command-id>
```

Settings metadata follows one generated pattern:

```text
settings.item.<kind>.<field>.name
settings.item.<kind>.<field>.description
settings.value.<field>.<raw-value>
```

`<kind>` and `<field>` are the kebab-case configuration identifiers. The raw
configuration field and value are never translated when settings are written
back to disk; only their visible labels are localized.

## Extraction and synchronization rules

`python scripts/i18n_audit.py` uses source-shape regular expressions to collect
four kinds of translation references:

- literal keys passed to `I18n::text` and `I18n::text_signal` in Lapce UI code;
- fields and descriptions declared by `CoreConfig`, `EditorConfig`, `UIConfig`,
  and `TerminalConfig`;
- Lapce commands declared with `strum(message = ...)` and `serialize = ...`;
- Floem Editor Core commands declared with the same `strum` annotations.

The command and settings patterns match stable Rust source annotations rather
than individual command or field names. The locale files are parsed as TOML,
not with regular expressions. In addition, the audit scans obvious raw UI
constructor calls such as `text("...")`, `label("...")`, and file-dialog
`.title("...")` and reports them as untranslated candidates. This candidate
list requires review because punctuation, product names, and framework/API
values can look like translatable text.

The audit then checks:

- matching key sets between English and Simplified Chinese;
- a name and description for every visible settings field;
- a locale entry for every extracted Lapce/Floem command;
- Chinese text in every Simplified Chinese settings name and description.

Synchronize the two runtime locale tables from extracted source keys with:

```powershell
python scripts/i18n_audit.py --sync-locales
```

The command updates `en.toml` with extracted English metadata where a key is
new, preserves existing Chinese translations in `zh-CN.toml`, and adds an empty
Chinese value for new keys. It never translates Chinese text. Fill new Chinese
values manually, then run the script without `--sync-locales` to audit the two
tables.

The synchronization command deliberately does not translate values. It
rewrites both files in one stable, lexicographic key order while preserving
existing values. Empty Chinese values are incomplete entries and must be
filled before the locale is considered complete.

## Exclusions

Do not translate command IDs, configuration identifiers, raw configuration
values, paths, filenames, Git refs, logs, diagnostics, user content, or
third-party plugin metadata. Fixed configuration choices may have translated
display labels, but their stored values must remain unchanged.
